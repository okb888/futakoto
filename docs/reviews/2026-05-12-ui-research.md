| パステル中心 | 視覚疲労を軽減する柔らかい色調 | Finch、Pookie、Daylio |
| くすみ系ナチュラル | sage green、テラコッタ、砂色系 | LoveNudge、wellness系全般 |
| ウォームパープル | 感情・精神的つながりを表現 | Paired、Kindu、Moodnotes |
| コーラル・ピンク | ロマンティック・温かみ | Couple、Avocado |
| クリーン白地 | 医療的清潔感と親しみの両立 | Streaks、MinimaList、COUPPLY |

**sage（くすみグリーン）の評価**: 研究では「sage greenは落ち着き・バランス・信頼・上品な洗練を伝え、groundedでelevatedな感覚」とされる。wellness・ライフスタイル・ミニマルブランドに最適。ふたことのsageカラー選択は方向性として正しい。

#### NGパターン

- 過度に鮮やかな原色（視覚疲労・「安っぽさ」の原因）
- 色数が多すぎる（3色以上のアクセントカラーは散漫に見える）
- 感情色と背景色のコントラスト不足（WCAG 2.0では3:1以上必要）
- 気分ヒートマップで色相のみに依存（色覚多様性への配慮不足）

#### 現状のふたことの評価

`COLORS`定数を分析すると:
- primary（#7B9E87 sage green）: 良好。一貫して使用されている。
- ai（#7C5BB7 パープル）: AI機能との色分けが明確で優れている。
- partner（#E58B8B ピンク）: パートナーの投稿を色分けする設計は良い。
- **課題**: borderSoft（#F0F0F0）と background（#FAFAF8）の差が小さく、カード境界が曖昧になりやすい。

### 2-2. タイポグラフィ

#### フォントサイズ階層（iOS標準）

| 役割 | サイズ | fontWeight | 用途 |
|------|--------|-----------|------|
| 大見出し | 22〜24pt | 700 | 画面タイトル |
| セクション見出し | 17〜18pt | 600 | グループタイトル |
| ラベル | 14〜15pt | 600 | フォームラベル |
| 本文 | 14〜16pt | 400 | カードメモ・説明文 |
| 補足 | 12〜13pt | 400〜500 | 日付・メタ情報 |
| キャプション | 11pt | 400 | バッジ・タグ |

#### 日本語アプリの注意点

1. **行間（lineHeight）**: 日本語は文字が密集しやすい。`lineHeight: 本文サイズ × 1.6以上`が読みやすい。現状のふたこと（lineHeight: 20、fontSize: 14）は1.43倍。**最低でも1.6倍（22〜24）が望ましい。**
2. **フォントウェイト**: iOS日本語は`fontWeight: '700'`でも細く見えることがある。見出しは`letterSpacing`の微調整も検討。
3. **ラベルとボディの差**: 現状のふたことは`label`が14pt 600、`cardMemo`が14pt 400。サイズが同じでウェイトのみ違う。**ラベルを13pt 600、本文を15pt 400**などサイズ差をつけると階層が明確になる。

### 2-3. 余白・グリッド

#### 8pxグリッドシステム

Material Designが提唱する8pxグリッドは、iOS開発でも標準的に採用される。

| 用途 | 値 |
|------|-----|
| 最小マージン | 8px |
| 標準パディング | 16px |
| セクション間 | 24px |
| 大きな余白 | 32px〜48px |

**現状のふたことの課題**:
- `marginHorizontal: 16`（カード）→ 適切
- `paddingTop: 12`（リスト上部）→ やや狭い。16〜20が望ましい
- `marginBottom: 10`（カード間）→ やや狭い。**12〜16が標準**
- `padding: 16`（カード内）→ 適切
- カレンダー画面など一部で余白の一貫性が不足

### 2-4. カード・リストUI

#### 投稿表示カードの設計パターン

優秀なアプリ（Daylio, Moodnotes, Between等）から抽出したパターン:

1. **左ボーダーカラー**: ふたことは実装済み（気分色）。これは正しい判断。
2. **シャドウ vs ボーダー**: iOS標準はシャドウ（shadow*プロパティ）。ふたことは現在ボーダーなし+シャドウなし。**微細なシャドウ追加でリフト感が出る。**
3. **カード角丸**: 現状の`borderRadius: 12`は適切。16まで上げると「より柔らかい印象」に。
4. **カード間隔**: 現状の`marginBottom: 10`をより広く（12〜16）すると間延びせず読みやすい。
5. **絵文字サイズ**: `cardEmoji`が28px。32pxに拡大すると感情の訴求力が増す。

### 2-5. タブバー設計

#### Apple Human Interface Guidelines準拠

- アイコンサイズ: 25×25 pt（最大48×32 pt）
- ラベルサイズ: **11pt**
- タブ数: 3〜5個（ふたことは5タブ：ホーム・投稿・相談・カレンダー・お気に入り＋設定）
- アクティブ: アクセントカラー（sage green）100% opacity
- 非アクティブ: グレー低opacity
- iOS 26では「Liquid Glass」浮遊タブバーが登場（将来対応の参考）

**現状の課題**: タブバー自体の実装は標準的。アイコンの選択と統一感が「素人っぽさ」の一因になっている可能性がある（phosphor-react-nativeは品質が高いので問題は少ない）。

### 3-3. カレンダー画面（`app/(app)/calendar.tsx`）

#### 現状の問題点

1. **気分ヒートマップの視認性**: MOOD_COLORSは`#E57373`（赤）〜`#81D4FA`（水色）の5段階。色相が多様すぎてヒートマップとして読みにくい。
2. **アクセシビリティ**: 色のみで気分を識別しており、色覚多様性への配慮が不足。
3. **スコア1（赤）とスコア5（水色）が「どちらが良い？」と直感的でない**: 一般的なヒートマップは同一色相の濃淡で表現するほうが認知しやすい。

#### 具体的改善提案

**A. 気分カラーをsage系単色グラデーションに変更（`lib/mood.ts`）**

```diff
- export const MOODS = [
-   { score: 1, emoji: '😣', label: 'つらい', color: '#E57373' },
-   { score: 2, emoji: '😔', label: 'しんどい', color: '#FFB74D' },
-   { score: 3, emoji: '😐', label: 'ふつう', color: '#FFF176' },
-   { score: 4, emoji: '🙂', label: 'まあまあ', color: '#AED581' },
-   { score: 5, emoji: '😊', label: 'いい感じ', color: '#81D4FA' },
- ] as const;
+ export const MOODS = [
+   { score: 1, emoji: '😣', label: 'つらい', color: '#D4A0A0' },   // くすみピンク（控えめ）
+   { score: 2, emoji: '😔', label: 'しんどい', color: '#C8BFA8' }, // くすみベージュ
+   { score: 3, emoji: '😐', label: 'ふつう', color: '#B8C4B0' },   // くすみグリーン中間
+   { score: 4, emoji: '🙂', label: 'まあまあ', color: '#8EAF98' }, // sage中間
+   { score: 5, emoji: '😊', label: 'いい感じ', color: '#6B9678' }, // sage濃い
+ ] as const;
```

**代替案（ヒートマップを「良い=濃い」に統一したい場合）**:
sage系単色の濃淡5段階。最も薄いものをスコア1、最も濃いものをスコア5とすることで「良い状態=より色が濃い」という直感的マッピングが可能。ただし絵文字と組み合わせるため、色相変化案（上記）でも十分。

**B. ヒートマップセルへの形状補助**

アクセシビリティ向上のため、色に加えてサイズ差を導入:

```tsx
// カレンダーのdotスタイルに適用
const dotSize = 4 + (score - 1) * 1.5; // score 1 → 4px, score 5 → 10px
```

## 5. 「素人っぽさ」の根本原因と対策まとめ

類似30件の調査から、ふたことの「素人っぽさ」の主因は以下3点に集約される。

### 原因1: 奥行き感のなさ（Flatness）

優秀なアプリはカードに微細なシャドウ（shadowOpacity: 0.05〜0.1）を使い、UI要素に奥行きを与えている。ふたことはカードが背景と同じ平面に見える。

→ **対策**: EntryCard、投稿フォームの入力エリア、保存ボタンに微細なシャドウを追加（即改善）。

### 原因2: タイポグラフィの階層不足

見出し・ラベル・本文・キャプションのサイズ差が小さく、情報の重要度が視覚的に伝わりにくい。特に日本語は文字が密になりがちで行間の不足が「素人感」を生む。

→ **対策**: ラベルサイズを13ptに、本文行間を22〜24に統一（即改善）。

### 原因3: インタラクションフィードバックの弱さ

テキスト入力フォーカス時の視覚変化がない、ボタンが「押せる感」を演出していない。Streaks（Apple Design Award受賞）のような優れたアプリは「何かが起きている」感覚を常に与える。

→ **対策**: フォーカス状態の実装、ボタンの色付きシャドウ追加（即〜中期改善）。
