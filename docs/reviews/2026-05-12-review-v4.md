## A. App Store 審査対策

### A-1. 🚨 PrivacyInfo.xcprivacy（致命）
- **現状**：`app.json` infoPlist に Privacy Manifest 設定なし。`ios/` ディレクトリ未生成（EAS Build 未実行）
- **対応**：`expo-build-properties` plugin で privacyManifest を追加。`expo-notifications` `expo-clipboard` `firebase` の対応版を確認
- **工数**：2h

### A-2. 🚨 Apple Sign-in（致命）
- **現状**：`app/login.tsx` はメール/パスワード認証のみ。v3 release-status.md で Google ログインを B スレッド実装中
- **判断ポイント**：
  - 案1：メール/パスワードのみで通す → Apple Sign-in 不要（推奨：5/31提出スコープを最小化）
  - 案2：Google + Apple Sign-in 両方実装 → 0.5〜1日工数追加
- **本日5/13中にスコープ確定**

### A-3. ⚠️ AI送信同意UI（高リスク）
- **現状**：`web/privacy.html` L130-132 に「Gemini API に送信」記載あり。**ただしアプリ内の明示的同意フローなし**
- **対応**：`components/AiConsentModal.tsx` を新規作成。`UserProfile.aiConsentAcknowledged: boolean` を追加し、未同意なら初回AI利用時にモーダル表示

### A-4. ⚠️ NSUsageDescription キー網羅（高リスク）

- **対応**：`expo-notifications` `expo-clipboard` 等の必須キーを app.json に追記

### A-5. ⚠️ コンテンツレーティング（高リスク・中対応）

## B. コード品質・残課題

### 🔴 緊急

#### CQ-001: `Entry.createdAt: any` 型統一未着手
- **ファイル**：`lib/db.ts:29, 39, 52, 60, 68, 88`
- **影響**：クライアント側 40箇所以上で `.seconds` `.toDate()` 散在。`app/(app)/index.tsx:88` `calendar.tsx` `post.tsx:38` でガードが累積
- **対応**：`createdAt: Timestamp | { seconds: number; nanoseconds: number }` を明示
- **工数**：0.5日

#### CQ-002: ホームの混合ソート不安定
- **ファイル**：`app/(app)/index.tsx:76-98`
- **問題**：`getRecentEntries(uid, 50)` + `getPartnerSharedEntries(partnerUid, 50)` を直線ソート。相手の最新が割り込むと自分の古い分が消える
- **対応**：自分/相手の limit を 100 に増やすか、別取得して時系列上位 60件に絞る
- **工数**：0.3日

#### CQ-003: `premium` フィールドの Firestore Rules 保護不足 🚨（BLOCK-4と同一）
- **ファイル**：`firestore.rules:19-29`
- **問題**：update ルールの `hasOnly` に `premium` を含む除外指定がない。クライアントから `premium: true` を直書き可能
- **対応**：update/create 両方で `premium` `premiumExpiresAt` `aiCreditsMonth` 等を Cloud Functions only に
- **工数**：0.2日

### 🟡 中

- **UI-001**：`components/EntryCard.tsx:106, 148` に `#fff` リテラル残存。`index.tsx` `calendar.tsx` `post.tsx` でも影色・枠線色が直書き。v3で「完了」とされたが部分実装
- **FN-001**：`hooks/useConsultSession.ts:192-199` の `handleStartNewConversation`、session作成失敗時のエラーハンドリングが薄い
- **FN-002**：aiDraft / aiDraftOptions のネットワーク切断時の draft復帰がない

### 🟢 低

- **CQ-004**：`lib/db.ts:233-243` `getRecentConsultations` がデッドコード。`calendar.tsx` から実際は参照されていない
