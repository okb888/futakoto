# ふたこと 集客戦略・SNS運用方針

**策定日**: 2026-05-09
**目標**: 2026年8月31日までに月額¥500の課金が1人発生
**事前検死v2 対応**: 🔴 U13（流入導線がない）/ B01（初期DLが2桁で母集団不足）

> このドキュメントは「ふたこと」のリリース前後の集客方針を定めた上位文書。
> 発信素材の詳細は [`content-stock.md`](./content-stock.md) を参照。
> 全体ロードマップは [`release-status.md`](./release-status.md) E. SNS運用 / F. LP修正 と接続する。

## 1. 構造的論点（先に押さえる前提）

### 1-1. 「夫婦両方に届ける」のはほぼ不可能
夫婦アプリの最大の壁は U01「奥さんが入れない」。**まず片側（主に妻側）に刺さる導線を作り、その人がパートナーを誘う設計**にしないと、DL数だけ伸ばしても課金まで届かない。

岡部は夫側の当事者なので、発信の主軸は「夫から見た夫婦のしんどさ」だが、**ターゲット読者は妻側**になる、というねじれを意識する。

### 1-2. 8月課金1人の本質は「分母×CVR」ではなく「強い1組」を作ること
3.7ヶ月で大規模流入は無理。**β配布の同僚2組+奥さん3ペア → そこから自然に滲み出る口コミ → リアル知人圏で20-50DL → そのうち1組が課金**、というスモールパス。

SNSは「広く撒く」より「深く刺さる発信を残しておく」（検索流入用）の優先度が高い。

### 1-3. 最大の集客資産は『離婚を一日で覆した3/11の物語』とその周辺の体験記録
これは岡部の当事者性そのもので、競合（LINE / Pairs / Tangerine）は絶対に持てない武器。**プロダクト紹介より、この体験を語る発信のほうが、夫婦アプリの文脈では届きやすい**。ただし家族・プライバシー配慮が必須（後述）。

## 2. ターゲット定義

### プライマリ：「諦めかけている妻」（妻側ペルソナA）
- 30代前半／第一子0-3歳／産後1-2年経過
- 夫は協力的なつもりだが、「ねぎらわれてない」という渇きが慢性化
- LINEは事務連絡、夫婦の話はもう「した気にならない」
- 「離婚」とまで思ってないが、1年後の関係を想像できない
- **検索行動**: 「夫 話聞いてくれない」「産後クライシス いつまで」「夫婦 すれ違い」

### セカンダリ：「諦めかけている夫」（夫側ペルソナB＝岡部自身の過去）
- 30代／妻の不満を察するが「何を言っても地雷」状態
- 言葉を選びすぎて結果的に何も言えない
- 男性は相談相手がいない。AIに壁打ちしたいニーズが潜在
- **検索行動**: 「妻 不機嫌 原因」「家事育児 してるのに」「夫婦 諦め」

### 設計上のねじれ
- **発信主体は夫（岡部）** → **メイン読者は妻側A**
- 「夫がここまで考えていたと知って驚く」という構造で妻側に刺さる
- 同時に夫側Bは「これは俺だ」と共感する → 夫から妻に渡す動線

## 3. メッセージ階層

### 一階：中核メッセージ（=岡部の思想）
> **「関係が終わっているのではなく、ねぎらい機能が止まっているだけかもしれない」**

3/11の物語の最大の発見。「冷めた=終わり」ではなく「機能停止=再起動可能」。**ふたことは再起動装置**、と位置づける。

### 二階：プロダクト訴求コピー
- メイン: **「離婚を覚悟した日に、一日で景色が変わった。あの夜を再現したくて作りました。」**
- サブ: **「夜寝る前の30秒を、ふたりのために。」**（既存LPコピー継続）
- 機能訴求は二の次。「誰が・なぜ・どんな経験から作ったか」が一階

### 三階：チャネル別の入り口メッセージ
| チャネル | 入り口 | 機能 |
|---|---|---|
| note | 「離婚を覚悟した日、一日で景色が変わった話」 | 検索＋深い共感（長期資産） |
| X | 「夫婦のしんどさを、夫側から書きます」 | 共感者囲い込み・拡散 |
| IG | アプリスクショ + 一言エッセイ | 妻側ペルソナへのリーチ |
| LP | 「離婚を覚悟した日に作り始めたアプリです」 | 訪問→DLの動機転換 |

## 4. チャネル評価と優先度

| チャネル | 想定流入 | 着手コスト | 妻側到達 | 優先度 |
|---|---|---|---|---|
| **note 体験記事**（夫婦の話・AI開発の話） | 中（検索流入が長期で効く） | 中 | ◎ | 🔴最優先 |
| **同僚β + リアル口コミ** | 数件だが課金確度最大 | 0 | ◎ | 🔴最優先 |
| **App Store ASO**（タイトル・キーワード） | リリース後の継続流入 | 低 | ◎ | 🔴必須 |
| **X 個人発信**（開発過程＋夫婦エッセイ） | 低-中（フォロワー次第） | 低 | △ | 🟡 |
| **Instagram**（カップル/育児タグ） | 中（妻側に届きやすい） | 中 | ◎ | 🟡 |
| **高松ローカルメディア**（タウン誌・地方紙） | 不確実だが他にない切り口 | 中 | ○ | 🟡検討 |
| **尾原コミュニティ・AI個人開発界隈** | 低（DLは増えるが妻側に届かない） | 低 | × | 🟢 補助 |
| **プロダクトハント / Zenn 等技術系** | 開発者DLのみ・妻側0 | 低 | × | 🟢 補助 |

## 5. note 運用方針

### 中核資産としての位置づけ
note を**集客の主戦場**とする。理由は (1)長文の文体が岡部の当事者性と相性が良い (2)検索流入が長期資産になる (3)妻側ペルソナの「夫婦 すれ違い」検索に届きやすい。

### 5本完結シリーズ構成
詳細とストック対応は [`content-stock.md`](./content-stock.md) §3 を参照。

| # | 仮タイトル | 想定公開時期 |
|---|---|---|
| 1 | 「子どもが、立った」または「冷蔵庫という、川の中の石」 | 6月リリース週 |
| 2 | 「『疲れてる？』と聞いた日に、何かが変わった」 | 6月中 |
| 3 | 「離婚を覚悟した日、一日で景色が変わった話」 | 6月下旬 |
| 4 | 「ワンオペを1日体験して見えた、ねぎらい機能が止まる構造」 | 7月上旬 |
| 5 | 「言葉にならないことを、言葉にする装置を作った」（プロダクト紹介） | リリース直後 |

### 設計思想
- 1本目は機微度が低く、人柄・文体が伝わる詩的な記事から入る（信頼を築く）
- 3本目に3/11を配置することで、それまでに読者との関係性が温まっている
- 5本目で初めてプロダクト訴求。それまでは「物語」「気づき」を提供する

## 8. プライバシー運用ルール（家族領域を出すための歯止め）

3/11の体験を中核資産にする前提として、**3つの不可侵ライン**を設定する。

### 8-1. 不可侵ライン
1. **妻の発言は事前許諾を得たもののみ引用**
   - 引用したnoteは事前に見せて承認をもらう（家庭の問題を一方発信しない）
2. **子どもは固有名詞・写真・年齢の特定情報を出さない**
   - 「赤ちゃん」「乳児期」「1歳前後」までで止める
3. **「離婚を覚悟した」までは書いてOK、「離婚を切り出した」は書かない**
   - 事実関係の解釈余地を残す

### 8-2. 妻同意の運用
- 機微度🔴🟠（[`content-stock.md`](./content-stock.md) §0 参照）の素材は note 公開前に妻に下書きを見せる
- 妻の発言を直接引用する場合は引用許諾を文書で残す
- 引用許諾がもらえない箇所は「相方」「片方」など抽象化する

### 8-3. 思想の表明としての制約
これは集客上の制約であると同時に、**プロダクト自体の倫理性の表明**にもなる。「妻に見せる前提で書く」というプロセスを公開すれば、それ自体が「ふたことの思想」と一致する発信になる。

## 10. ASO（App Store最適化）方針

リリース後の継続流入の土台。**実装はリリース前最終週に集中**。

### 必須対応
- [ ] アプリ名: 「ふたこと」（既定）
- [ ] サブタイトル: 「夫婦の気持ちを30秒で共有」のような検索キーワードを含む短文
- [ ] キーワードフィールド: 「夫婦, 産後, ワンオペ, 育児, すれ違い, 気持ち, 日記, ペア, パートナー」
- [ ] スクリーンショット5枚（カレンダー画面・投稿画面・AI壁打ち画面・ペアリング画面・LPと統一されたコピー）
- [ ] プロモーションテキスト（更新で順位影響なし）

### 検索順位を狙うキーワード候補
- **第一群（メイン）**: 「夫婦 アプリ」「夫婦 日記」「産後 すれ違い」
- **第二群（サブ）**: 「ワンオペ 育児」「夫婦 共有」「気持ち 整理 アプリ」
