# aiConsult eval テスト方針

---

## 目的

`aiConsult`（壁打ち機能）のreflection精度を確認し、プロンプト改善につなげる。
A案（現行）とB案（改善候補）を同一サンプルで比較し、採点はClaude Codeが担う。

---

## テスト方針

- **1ケースあたり5サンプル**で複数パターンに耐えられるか確認する
- **A/B並列実行**：同一サンプルをA・B両プロンプトで実行し出力を比較
- **採点者はClaude Code**（Gemini自己採点は使わない）
- **messageDraftは評価対象外**（壁打ちとメッセージ生成の分離方針に伴い廃止予定）
- **C案以降の検討**：ケース完了ごとにA/B両案の弱点を分析し、必要であればC案プロンプトを作成して同ケースを再実行する。PLAN.mdのプロンプト変遷ログに記録する。

## C案以降の検討フロー

```
各ケース完了
  ↓
A/B両案の弱点を分析
  ↓
両案とも弱い共通パターンがある？
  ├── Yes → C案プロンプト（prompt-c.ts）を作成 → 同ケース再実行 → 比較
  └── No  → 次のケースへ進む
```

C案を作った場合はPLAN.mdの「プロンプト変遷ログ」に変更内容と理由を追記する。

## 出力ファイル

| ファイル | 内容 |
|---------|------|
| `results/{variant}_{caseId}_{date}.json` | 各実行のJSON |
| `results/all_results.csv` | 全結果を1枚にまとめたCSV（目視確認用） |
| `REPORT.md` | 採点サマリー・弱点分析・判断 |

### CSVの列構成
```
variant, caseId, sampleId, caseLabel, input, reflection, reflectionLength, timestamp
```

---

## 実行方法

```bash
cd futakoto/eval

# 特定ケースのA/B並列実行
npx tsx run.ts A case-04 & npx tsx run.ts B case-04 & wait

# 全ケース一括実行
bash run-all.sh
```

---

## ファイル構成

```
eval/
  PLAN.md        # このファイル（テスト方針）
  REPORT.md      # 実施結果・採点サマリー
  cases.ts       # テストケース・サンプル定義
  run.ts         # 実行スクリプト（variant・caseフィルタ対応）
  run-all.sh     # 全ケース一括実行スクリプト
  prompt-a.ts    # A案プロンプト（現行と同一）
  prompt-b.ts    # B案プロンプト（改善候補）
  prompt-c.ts    # C案以降（必要に応じて生成）
  results/       # JSON・CSV出力
```

## 採点基準（reflectionのみ）

| 観点 | 評価内容 |
|------|---------|
| 気持ちの読み取り精度 | 1〜5（的外れ=1、深く汲めている=5） |
| 問いかけの質 | 感情寄り／状況確認／余計な断言 |
| 疲弊・諦めの扱い | 入力にある場合に薄めず拾えているか |
| 葛藤の両立 | 「〇〇だけど△△」という並立を消していないか |
| 文字数 | 200文字以内に収まっているか |
| ラリー継続性（case-06のみ） | 前ターンを踏まえて前進しているか・繰り返しになっていないか |
